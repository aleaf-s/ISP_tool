# CLUT 格式与验证范围（V0.4.56）

## 软件处理模型

输入按现有彩色图读取规则转换或假定为编码 sRGB（D65）。本功能不进入 RAW ISP 或 AWB 仿真，不改它们的算法。取色调色与 CLUT 调色互斥，选择后各自保留参数。

- HS 节点：H = 0, 15, …, 345°；S = 0, 0.125, …, 1，共 24×9。
- ΔHue：−180…180°；ΔSat：−1…1，加法偏移。结果 Hue 环绕，S 限制到 0…1；S=0 一列固定为零，保护中性灰。
- HS 采用周期 smoothstep 插值；映射中不修改 HSV Value。将结果烘焙为 33³ 均匀 RGB 节点，图像使用四面体位移插值；不是逐像素直接 HSV 运算。
- 33³ 节点精确遵循上述 Value 规则，但节点之间的 RGB 插值会产生近似误差，不承诺连续域中 Value 完全不变。Hue 调整很大、邻点差异很大时，也不保证无折叠或单调性。
- PNG 8-bit 与 TIFF 16-bit 导出和精细预览共用处理函数；量化、Alpha 合成及显示缩放不同，不承诺屏幕截图与 16-bit 文件逐像素相同。处理不加入额外 Gamma 或曝光。
- 编辑数字按用途显示（ΔHue 一位，ΔSat 三位），Tooltip 显示更高精度；未编辑字段不会因显示格式而量化。拖动仅重绘编辑器，不更新主图。点击“应用”后才更新图像，沿用现有异步最新结果校验和原分辨率视口机制，不承诺固定帧率。

## 编辑草稿与应用

CLUT 编辑器在可调整大小/最大化的独立窗口内。窗口底部的应用按钮固定可见；关闭仅隐藏窗口，切工具时隐藏，不丢弃草稿。主界面右侧也可应用和重新打开调试窗口。

每张图分别持有网格草稿、数字草稿和已应用网格。Enter/失焦、粘贴、拖动结束、撤销/重做和加载参数只改变草稿；“应用”会先原子校验所有未提交数字，然后更新已应用快照。重复点击不会重复计算。撤销应用后的编辑不会立即撤销图像效果，需再点击应用。

表格编辑支持点击其他格或 Tab / Shift+Tab 确认当前输入并继续编辑，无需按 Enter。非法输入阻止相应导航并保留文本；普通输入框失焦也会验证。以上均只更新草稿。

“恢复到上次应用”清除未提交数字和正在拖动的草稿，恢复已应用网格及导入设备表，不重新处理图像；网格恢复可撤销，但撤销也只影响草稿。加载不会自动应用。图像和 CLUT 导出在存在未应用修改时明确阻止，避免预览与导出不同步。切图时保留两套状态，另一张图不会继承它们。

## 取色与邻域编辑

取色使用原图 5×5 平均 RGB（不是显示叠加色），转换 HSV 后定位最近 HS 节点。低彩度或接近黑色时落到中性轴，不对不稳定 Hue 作承诺。目标色为该平均色经过草稿 33³ CLUT 的结果；它不是邻域所有像素处理后的平均值。

取色读数显示 HSV（H°、S/V 0～1），中性色 H 显示“—”。取色后默认进入 Delta Hue 表，原先处于 Delta Sat 时保持该表；自动滚动并高亮对应单元格，同时显示节点行列。定位采用原色而不是目标色。

邻域距离以网格节点为单位：Hue 方向使用 24 行的最短环绕距离，Sat 方向使用列距离，两者取欧氏距离。范围 R=0 仅选中节点有权重；R>0 时 t=clip(1−distance/R,0,1)，权重为 (1−smoothness)×t + smoothness×t²×(3−2t)。范围边缘权重为零；S=0 列始终锁定。平滑强度在 0…1 之间，仅改变新调整的衰减形状，不重新平滑整个已编辑网格。

单点输入/拖动把选中节点的增量按权重分配给邻点，Hue 增量取最短角路径，保持已有邻点调整。ΔSat 邻点越界则拒绝整个编辑，不静默裁切。批量粘贴和重置不扩散；多个显式数字草稿整体校验，显式目标优先。结果仍使用同一 HS 插值和 RGB CLUT 烘焙链路，不新增图像处理阶段。

橙色叠加是当前选中节点/邻域的潜在影响权重，使用同一 HS 插值采样；中性像素权重为零，并考虑 Alpha。掩码缓存在缩略图尺度，随预览几何变换显示，不改变计算图像、导出或读数，不代表实际颜色差值或空间蒙版。所有历史调整的总影响不由该叠加表示。

邻域设置、取色样本和叠加开关按图像在会话内保存；设备 TXT 不保存这些工具状态，也不保存软件 HS 控制点历史。

## TXT 导入与继续调整

界面只提供 TXT 参数导入导出，JSON 入口已移除。旧 JSON 函数只为历史代码兼容保留，不可用于存储新导入的设备表。不会把 JSON 改后缀伪装为设备 TXT。

CLUT 导入检查全部 5508 个整数及填充槽后，才替换当前图像的草稿；有未应用修改时先确认。点击应用后，17³ 节点按 `RGB + Delta/1023` 构造软件查找表，以四面体插值用于预览及图像导出。插值前不裁切导入节点，输出阶段裁切到 0～1；默认均匀 RGB 节点、单位增益仍是假设。没有修改时直接复用原始 5508 个整数导出，不重新量化。非法文件不会覆盖当前草稿。

设备 3D LUT 不能唯一反推出二维 HSV 参数。导入后 HS 网格置零并标注“额外调整”：在原输入 RGB 域计算软件 HS 位移，加到导入设备表的结果上，再裁切并烘焙 33³ 软件 LUT。取色、影响范围仍按原输入颜色定位。重置表仅清除额外 HS 调整，保留导入设备表；撤销和恢复上次应用包含设备表。调整后的导出重新采样到 17³，检查范围后打包；不保证与软件 33³ 结果完全相同，保留重建误差反馈。

保存使用同目录临时文件、flush/fsync 和原子替换。序列化和校验失败时不覆盖旧目标。无自动多图工程保存；需要下次继续时显式导出 TXT。重新导入可继续叠加调整，但不恢复原软件控制点历史，文件不会自动上传。

## HiSilicon TXT（实验）

### 官方工具指南核验（2026-09-24）

用户提供的 [Hi3403 图像质量调试工具指南：CLUT](https://docs.hisilicon.com/repos/pegasus/zh-CN/master/图像质量调试工具使用指南/图像质量调试工具使用指南.html#clut) 区分了 HSV 调试记录与设备 LUT，推荐用 HSV 记录继续原调试过程，并指出从 LUT 导入得到的 HSV 显示存在偏差。它确认了 CLUT 以输入/目标颜色构建 RGB 三维映射、强度 1024 对应 1×，还强调 Gamma 表对调试的影响。本工具的设备表导入仅作为基础 LUT 和额外软件调整，不称为原 HSV 工程恢复。该章节未提供六字段 HSV TXT 的逐字段单位、编码或转换公式，仍不足以实现可信的兼容 HSV 工程导入导出。截图 sRGB 预览也不是设备 CLUT 输入和 Gamma 链路的完整替代。

打包适配依据 [Huawei CANN `hi_isp_clut_lut` 官方结构说明](https://www.hiascend.com/document/detail/zh/CANNCommunityEdition/900beta2/API/ispapi/ispdevapi_0276.html)，并使用用户提供的 TXT 样例复核。该说明不是用户芯片/SDK 已匹配的证明。

实现的文件布局：

- 17³ 个 RGB 差值节点，数组内部索引 `[r,g,b,channel]`。
- 每个分量使用 10-bit 补码，合法整数 −511…511；R 放低位、G 放中位、B 放高位，合为一个 30-bit 非负整数。
- 按 R/B/G 坐标奇偶分为八组，组内 R 最快、G 最慢；前四组和后四组分别交错排列，未使用槽为零。
- 共 5508 个十进制整数；9 个一行，逗号分隔并保留尾逗号，共 612 行。

本工具生成新的 TXT 时，**暂定**均匀 17³ RGB 输入节点、差值乘以 1023、单位 CLUT 增益。使用 round-half-to-even，先检查合法范围，再补码打包。强烈调整超出范围会拒绝导出，不做静默裁剪。

导出时解包回读，并在 33³ 探针点比较软件 LUT 与重建 17³ LUT；状态栏 Mean/Max 为所有 RGB 分量的绝对误差（×255）。该数字只反映软件重建误差，不是硬件测量或设备仿真验收。
